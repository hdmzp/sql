쿼리는 쓴 순서대로 실행되지 않는다

세부 문법보다 이것부터 잡으면 “왜 여기서 별칭을 못 쓰지?” 같은 에러의 절반이 사라집니다. 아래 쿼리는 일부러 모든 절을 넣었어요. 다음 단계를 누르면 그 단계가 끝난 직후의 중간 결과가 보입니다. 지워지는 행은 취소선으로 표시돼요.

    전체 실행 순서

    1. FROM · JOIN
    2. WHERE
    3. GROUP BY
    4. HAVING
    5. SELECT (윈도우 함수 포함)
    6. DISTINCT
    7. ORDER BY
    8. LIMIT

    외우는 요령: “어디서(FROM) 무엇을 거르고(WHERE) 묶어서(GROUP BY) 또 거른 뒤(HAVING) 보여주고(SELECT) 정렬해서(ORDER BY) 자른다(LIMIT)”. 아래 규칙은 전부 이 순서에서 나옵니다. 에러 메시지도 MySQL 8.0에서 그대로 실행해 가져온 것이에요.

    ① WHERE에서는 SELECT 별칭을 쓸 수 없다

    WHERE(2단계)가 실행될 때 SELECT(5단계)는 아직 실행 전이라 별칭이 존재하지 않습니다.

    SELECT order_id, amount * 0.9 AS sale_amount
FROM orders
WHERE sale_amount >= 100000;
    ERROR 1054 Unknown column 'sale_amount' in 'where clause'

    식을 그대로 다시 쓰거나, 서브쿼리/WITH로 한 번 감싸서 바깥에서 별칭으로 거릅니다.

    ② WHERE에서는 집계함수를 쓸 수 없다 → HAVING

    WHERE는 그룹이 만들어지기 전(3단계 이전)이라 SUM, COUNT 같은 집계 결과가 없습니다.

    SELECT customer_id, SUM(amount) AS total
FROM orders
WHERE SUM(amount) >= 200000
GROUP BY customer_id;
    ERROR 1111 Invalid use of group function
    SELECT customer_id, SUM(amount) AS total
FROM orders
GROUP BY customer_id
HAVING SUM(amount) >= 200000
ORDER BY total DESC;
    HAVING으로 고치면 (3행)
    customer_idtotal
    1459000
    5320000
    3264000

    ③ ORDER BY는 별칭을 쓸 수 있다

    ORDER BY는 SELECT 뒤(7단계)라서 별칭이 이미 만들어져 있습니다. 위 쿼리의 ORDER BY total DESC가 그 예. (MySQL은 편의상 GROUP BY·HAVING에서도 별칭을 허용하지만, WHERE만은 절대 안 됩니다.)

    ④ 윈도우 함수는 감싸서 바깥에서 거른다

    윈도우 함수는 SELECT 단계에서 계산되므로 WHERE·HAVING에 직접 쓸 수 없습니다.

    SELECT order_id, amount,
       ROW_NUMBER() OVER (ORDER BY amount DESC, order_id) AS rn
FROM orders
WHERE rn <= 3;
    ERROR 1054 Unknown column 'rn' in 'where clause'
    WITH ranked AS (
  SELECT order_id, amount,
         ROW_NUMBER() OVER (ORDER BY amount DESC, order_id) AS rn
  FROM orders
)
SELECT order_id, amount, rn
FROM ranked
WHERE rn <= 3;

    쿼리를 짜는 사고 순서

    문제를 읽자마자 SELECT부터 쓰지 마세요. 아래 다섯 가지를 먼저 메모하면 쿼리가 거의 자동으로 나옵니다.

    1. 결과 한 행의 단위는? 고객 1명당 1행? 날짜 1일당 1행? 주문 1건당 1행? → 이게 곧 GROUP BY 기준. “~별”이라는 말을 찾으세요.
    2. 필요한 테이블은? 필요한 컬럼이 어느 테이블에 있고 조인 키는 무엇인가. → 0건인 행도 나와야 하면 그 테이블을 왼쪽에 두고 LEFT JOIN.
    3. 무엇을 거르나? → 원본 행 조건은 WHERE, 집계 결과 조건은 HAVING, 순위 조건은 감싼 바깥 쿼리. LEFT JOIN 오른쪽 테이블 조건은 ON.
    4. 무엇을 계산하나? → 합계·개수·평균, 조건부 집계(CASE), 순위·누적·이전 값(윈도우).
    5. 어떻게 보여주나? → 컬럼명(별칭), 반올림 자릿수, 정렬 기준과 동점 처리, 개수 제한.

    적용해 보기: “도시별 고객 수와 9월 매출을 구하라. 9월 주문이 없는 도시도 0으로 표시, 매출 큰 순”

    1. 한 행 = 도시 → GROUP BY c.city
    2. 도시는 customers, 금액은 orders. 도시가 빠지면 안 되니 customers 기준 LEFT JOIN
    3. 9월 주문만 → 오른쪽 테이블 조건이라 ON에 둔다 (WHERE에 두면 대전이 사라짐, 7장)
    4. 고객 수는 조인으로 행이 불어나니 COUNT(DISTINCT c.customer_id), 매출은 IFNULL(SUM(...), 0)
    5. 매출 큰 순 → ORDER BY sep_sales DESC
    SELECT c.city,
       COUNT(DISTINCT c.customer_id) AS customer_cnt,
       IFNULL(SUM(o.amount), 0)      AS sep_sales
FROM customers c
LEFT JOIN orders o
       ON o.customer_id = c.customer_id
      AND o.order_date BETWEEN '2026-09-01' AND '2026-09-30'
GROUP BY c.city
ORDER BY sep_sales DESC;
    결과 (3행)

    부산1129000
    대전10

    WHERE 조건

    원본 행을 한 줄씩 보면서 남길지 버릴지 정하는 단계입니다. 조건 결과가 참(TRUE)인 행만 남아요. 거짓과 NULL은 둘 다 버려집니다.

WHERE price BETWEEN 30000 AND 130000        -- 양 끝 포함 (30000 <= price <= 130000)
WHERE category IN ('가전', '뷰티')           -- 목록 중 하나와 같으면

WHERE NOT (a = 1 AND b = 2)                 -- 논리 연산: NOT > AND > OR 순서로 먼저 계산

    COUNT 3종의 차이

       COUNT(customer_id)          AS count_col,       -- 그 컬럼이 NULL이 아닌 행 수
       COUNT(DISTINCT customer_id) AS count_distinct   -- NULL 아닌 서로 다른 값의 수
FROM orders;

    JOIN

    테이블을 옆으로 붙입니다. 어떤 행이 남고, 어떤 행이 사라지고, 어떤 행이 복제되는지가 전부예요.

    • INNER JOIN (그냥 JOIN): 양쪽 다 짝이 있는 행만.
    • LEFT JOIN: 왼쪽은 전부 남기고, 짝이 없으면 오른쪽 컬럼을 NULL로 채움.
    • RIGHT JOIN: 반대. 보통은 테이블 순서를 바꿔 LEFT로 씁니다.
    • CROSS JOIN: 모든 조합(5명 × 6상품 = 30행). 날짜 × 상품 같은 “뼈대” 만들 때.
    • MySQL엔 FULL OUTER JOIN이 없습니다. LEFT JOIN과 RIGHT JOIN을 UNION으로 합칩니다(11장).

    서브쿼리에 이름을 붙여 위에서부터 차례로 쌓는 방법. 복잡한 문제일수록 단계를 나누고, 단계마다 SELECT * FROM 단계명으로 중간 결과를 확인하세요.

  GROUP BY customer_id

JOIN customers c ON ct.customer_id = c.customer_id
CROSS JOIN avg_total a             -- 1행짜리라 CROSS JOIN으로 붙여도 행이 안 늘어남

    윈도우 함수

    GROUP BY는 행을 접어 그룹당 1행을 남기지만, 윈도우 함수는 행을 그대로 두고 각 행 옆에 순위·누적합·이전 값 같은 계산을 붙입니다. 상급 문제의 대부분이 여기서 나와요.

    함수() OVER (
  PARTITION BY 그룹기준      -- 생략하면 전체가 한 그룹
  ORDER BY 정렬기준          -- 순위·누적·LAG에 필요
